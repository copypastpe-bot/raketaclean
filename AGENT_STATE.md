## Purpose

Один репозиторий, три службы. Корень — рабочий бот клининговой компании (заказы, лояльность, зарплата, касса, уведомления, админка, обмен с amoCRM, письма клиенту). `raketa-admin-bot/` — админ-бот владельца: amo_sync, ковры, календари, автозвонок, цепочка заказа, оплата по счёту, отклики на промо, «Повторный заказ» по оценке. `raketa-notify/` — служба оповещений (шина), поэтапное включение. Базу рабочего бота админ-бот только читает, в amoCRM пишет своей интеграцией.

## Known Limitations

- **Перезапуск `telegram-bot`** — по слову владельца; `sudo -n systemctl restart telegram-bot.service` у агента работает. FSM в памяти — перезапуск стирает. nginx — только владелец.
- **Служба оповещений: код обновляет только владелец** (`sudo rsync` агенту закрыт), `raketa-notify/docs/runbook.md` §8.
- **Выключатели админ-бота** — в его `.env`, обёрткой `sudo raketa-admin-bot-update --<ключ>` (`/usr/local/sbin`, обновляет себя при выкате: новые ключи — со следующего запуска). **Рабочего бота** — `/opt/telegram-bot/switches.env` (без комментария в строке флага), список — `docs/deploy.md`.
- **База на проде:** `psql -d clients_db` как `admin` (peer) — права на `public` по таблицам, новые (`promo_callbacks`, `order_close_reminders`, `autocall_manager_callbacks`) не видны; читать их — от роли `bot` (`DB_DSN` из `/opt/telegram-bot/.env`, не печатать). Миграции рабочего бота — от `bot` + строка в `schema_migrations`. Диагностика CRM — обёрткой: `--leads=<телефон>`, `--lead-ids=…`, `--stale`, `--autocall-exam` (только чтение, без перезапуска). Чистка — `--close-stale`, `--close-new-leads`, `--close-repeat-tasks` (без `-live` — просмотр). Любой запуск обёртки сначала кладёт код из `/home/admin/raketa-admin-bot` в app; новый ключ узнаётся со второго запуска после rsync.
- **Тесты:** админ-бот — `TEST_DB_DSN=postgresql://postgres@127.0.0.1:5432/adminbot_test .venv/bin/python -m pytest -q`; рабочий бот — `…/raketaclean_test .venv-wahelp/bin/python -m pytest tests/ -q`; через `rtk` только `rtk proxy …`. `timeout` на маке нет.
- **Исполнителям:** запрет `stash`/`worktree`/`merge`/`push`; сверка HEAD первым шагом; одна задача на субагента; ревьюерам тесты запрещены. Mechanic может упереться в потолок ходов без отчёта — проверить дерево и дифф самому.
- **Деплой:** рабочий бот — пуш → `git pull --ff-only` в `/opt/telegram-bot` → миграции → перезапуск; админ-бот — `rsync` (с согласия владельца) → `sudo raketa-admin-bot-update`.
- **WAHelp:** рабочий бот входит по логину один раз и на 401 заново не входит — скриптами под его учёткой не ходить. **АТС:** клиент робота при протухшем ключе сам получает новый; ключ — `/home/admin/.pbx.env` (не печатать).
- Папка `robot_amo` — боевой вход ковров. Прокси вне РФ — общая точка отказа трёх ботов.
