## Purpose

Один репозиторий, три службы. Корень — рабочий бот клининговой компании (заказы, лояльность, зарплата, касса, уведомления, админка, обмен с amoCRM, письма клиенту). `raketa-admin-bot/` — админ-бот владельца: amo_sync, ковры, календари, автозвонок, цепочка заказа, оплата по счёту, с 23.09 — сделки по откликам на промо. `raketa-notify/` — служба оповещений (шина), идёт поэтапное включение. Базу рабочего бота админ-бот только читает, в amoCRM пишет своей интеграцией.

## Known Limitations

- **Служба оповещений: код обновляет только владелец** — `sudo rsync` агенту не разрешён (есть только рестарт службы). Команда в `raketa-notify/docs/runbook.md` §8.
- **Права на чтение у `admin` (peer):** на `public.amocrm_unsorted_cards` выдано владельцем 23.09; на `public.promo_callbacks` — нет (видно через `to_regclass`, не содержимое). Роль `adminbot` видит новые таблицы `public` по умолчанию.
- **Выключатели админ-бота** — в его `.env`, только обёрткой `sudo raketa-admin-bot-update --<ключ>`; обёртка обновляет сама себя — новые ключи со второго запуска; после правки обёртки прогонять `--report`.
- **База на проде:** `psql -d clients_db` как `admin` (peer). Миграции рабочего бота — от роли `bot`: `psql "$(grep '^DB_DSN=' /opt/telegram-bot/.env | cut -d= -f2-)" -f <файл>`, значение не печатать. Журнал `public.schema_migrations` не ведётся (задача 19; 0014 и 0015 тоже не записаны).
- **Тесты:** админ-бот — `TEST_DB_DSN=…/adminbot_test .venv/bin/python -m pytest -q` (без переменной 85 пропусков); рабочий бот — `TEST_DB_DSN=…/raketaclean_test .venv-wahelp/bin/python -m pytest tests/ -q`; служба — `raketa-notify/` с `notify_test`. Через `rtk` только `rtk proxy … -m pytest`.
- **Исполнителям: запрет `stash`/`worktree` писать в промпт явно** — 23.09 исполнитель на Sonnet сделал `stash` при параллельной работе другого (ущерба не было). Отдельная копия (`worktree`) — только по слову владельца, через штатную изоляцию агента; после слияния убрать копию и ветку.
- **Экономия субагентов (решено 23.09):** проверка после правок — координатор по диффу; механика — Haiku. 23.09 по прямой просьбе владельца исполнители на Opus (исключение на два ТЗ).
