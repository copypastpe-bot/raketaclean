## Purpose

Один репозиторий, три службы. Корень — рабочий бот клининговой компании (заказы, лояльность, зарплата, касса, уведомления, админка, обмен с amoCRM и письма клиенту). `raketa-admin-bot/` — админ-бот только для владельца: amo_sync, ковры, два календаря, автозвонок, разбор удалённых заказов, с 23.09 — цепочка заказа и доводка оплаты по счёту. `raketa-notify/` — служба оповещений (шина), идёт поэтапное включение. Базу рабочего бота админ-бот читает только на чтение, в amoCRM пишет своей интеграцией.

## Current State

**`main` запушен.** Оба бота выкачены на `2fba506` (23.09, 13:13 админ-бот, 13:23 рабочий бот), служба оповещений — на `c1deddf`.

**Цепочка заказа в бою (ТЗ `docs/plans/2026-09-22-order-chain.md`, 12 задач, все закрыты).** Робот ведёт заказ одной цепочкой «запись календаря → лид воронки 1 → сделка воронки 2 → заказ мастера → оплата»:

- дочку автосделки берёт по служебному примечанию сейлзбота (`note_type=lead_auto_created`), а не «первую свободную»; таймер ожидания считает от передачи в работу (`AMO_CHILD_BY_NOTE=1`);
- удаление записи закрывает только сделку воронки 2 с датой; правка записи обновляет обе сделки; «занято» считается по номеру сделки; кнопки выбора сделки — с адресами и ссылками;
- сверка «номер + имя» записи с контактом сделки, расхождение → напоминание владельцу с кнопкой «Я разобрался», раз в сутки до 7 (`GCAL_CONTACT_CHECK_ENABLED=1`);
- мастер в «🧾 Заказ» после телефона выбирает запись календаря, если их две и больше на день (`ORDER_CALENDAR_PICK=1` в `switches.env`); заказ уезжает с номером записи и сделки, робот берёт её напрямую, номер заказа пишется в запись;
- оплата по счёту: робот доводит сделку после снятия ожидания оплаты (`WIRE_PAYMENT_ENABLED=1`, бой). Первый боевой круг 23.09 14:04 закрыл пять исторических заказов: 602 получил сумму, 639 переведён, 588/591/633 уже были закрыты руками — отметка молча.

Тесты: админ-бот 962 → **1075**, рабочий бот 356 → **367**. Уборки в выбор записи не входят (решение владельца, отдельным шагом).

## Known Limitations

- **Выключатели админ-бота живут в его `.env`** и ставятся только обёрткой (`sudo raketa-admin-bot-update --<ключ>`), не в `switches.env`; каждый ключ — рестарт службы. `bash -n` не ловит необъявленную переменную под `set -u` — после правки обёртки прогонять `--report` на сервере (23.09 такая ошибка чуть не сломала выкат).
- **База на проде читается как `admin` без пароля:** `psql -d clients_db` (peer), обе схемы. Миграции рабочего бота накатываются от роли `bot`: `psql "$(grep '^DB_DSN=' /opt/telegram-bot/.env | cut -d= -f2-)" -f <файл>` — значение не печатать. Журнал `public.schema_migrations` не ведётся (задача 19).
- **Тесты:** админ-бот — из его каталога, `TEST_DB_DSN=postgresql://postgres@127.0.0.1:5432/adminbot_test .venv/bin/python -m pytest -q` (без переменной 85 тестов пропускаются молча); рабочий бот — `TEST_DB_DSN=postgresql://postgres@127.0.0.1:5432/raketaclean_test .venv-wahelp/bin/python -m pytest tests/ -q` (без неё 16 пропусков); служба — из `raketa-notify/` с `notify_test`. Через `rtk` только `rtk proxy … -m pytest`.
- **Экономия субагентов (решено владельцем 23.09):** повторную проверку после круга правок делает координатор по диффу; ревьюеры тесты не запускают; исполнителям потолок ходов и запрет stash/worktree; механику — Haiku. Причина: 2,4 млн токенов субагентов на шесть задач, два раза упёрлись в лимит.
- **Правила проекта живут в двух местах**: `CLAUDE.md` и `AGENTS.md`; списки карт функций теперь в обоих плюс `raketa-admin-bot/CLAUDE.md` (карты есть у всех файлов длиннее 500 строк).
- **Папка `robot_amo` — боевой вход**: файл партнёра до 100 строк робот проведёт и заведёт сделки.
- Прокси вне РФ — общая точка отказа трёх ботов.
- **Деплой ручной, SSH `admin@91.200.150.68`.** Рабочий бот: `git pull --ff-only` в `/opt/telegram-bot`, миграции руками, рестарт по слову владельца. Админ-бот: `rsync` из `~/Projects/raketaclean/raketa-admin-bot/` в `/home/admin/raketa-admin-bot/`, затем `sudo raketa-admin-bot-update` (миграции применяет сам). Порядок для цепочки заказа: сначала миграция рабочего бота, потом админ-бот.
- **`sudo systemctl daemon-reload` агенту недоступен.** Рестарты трёх служб и `tee`/`mkdir` без пароля.
