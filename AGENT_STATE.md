## Purpose

Один репозиторий, теперь три службы. Корень — рабочий бот клининговой компании (заказы, лояльность, зарплата, касса, уведомления, админка, обмен с amoCRM и письма клиенту). `raketa-admin-bot/` — админ-бот только для владельца: amo_sync, ковры, два календаря, автозвонок, разбор удалённых заказов. `raketa-notify/` — новая служба оповещений (шина), пока не выкачена. Базу рабочего бота админ-бот читает только на чтение, в amoCRM пишет своей интеграцией.

## Known Limitations

- **Уровень записи журнала переходник берёт из текста строки, а не из метки systemd** — оба бота пишут голым `logging`, и systemd метит всё одинаково. Это предположение исполнителя, на живом journald не проверено: проверить при выкате.
- **Курсор журнала не переживает перезапуск службы**: после рестарта читается с текущего конца, короткий пробел возможен. Сознательный выбор ради простоты.
- **`notifications/outbox.py:626`** кладёт в журнал весь payload вебхука, там может быть телефон клиента. Код не трогали, защита — маскировка в переходнике.
- **rtk-обёртка врёт по pytest**: показывает «No tests collected» при реально прошедших тестах. Настоящий прогон — через `rtk proxy ... -m pytest`.
- **Папка `robot_amo` — боевой вход**: файл партнёра до 100 строк робот проведёт и заведёт сделки. Перед запросом файлов предупреждать.
- **Файлы, положенные на сервер руками, ломают штатное обновление** (`git pull` откажется перезаписать untracked-файл).
- **Бутстрап схем в коде создаёт таблицы с нуля, но не мигрирует существующие.** Миграции по существующим таблицам накатывать руками ролью `bot` до рестарта.
- Переотправка клиенту вторым каналом идёт медленно: по одному сообщению старше 10 минут, пауза 1-60 минут.
- Сообщения менеджеру по автозвонку идут без страховки: токеном рабочего бота в личку.
- Репетиция уборок не проходит путь «новый клиент» до конца: он ждёт автосделку сейлзбота.
- API amoCRM v4 сделки не удаляет: лишнее удаляет владелец руками, робот только закрывает.
- `recon/data/` и xlsx в корне содержат ПД и в git не попадают.
- Прокси вне РФ — общая точка отказа трёх ботов; резервные DNS с 15.09.
- Деплой ручной, SSH `admin@91.200.150.68`. Рабочий бот: `git pull --ff-only`, миграции руками, рестарт. Админ-бот — два шага: `rsync`, затем `sudo raketa-admin-bot-update`. NOPASSWD не покрывает `sudo -u adminbot`, `sudo -u postgres` и `sudo cp`.
- Тесты: корень — `.venv-wahelp/bin/python -m pytest tests/ -q` с `TEST_DB_DSN=postgresql://postgres@127.0.0.1:5432/raketaclean_test`; админ-бот — из его каталога с `adminbot_test`; служба — из `raketa-notify/` с `notify_test`.
