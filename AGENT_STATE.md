## Purpose

Один репозиторий, две службы. Корень — рабочий бот клининговой компании (заказы, лояльность, зарплата, касса, уведомления, админка, обмен с amoCRM и письма клиенту). Подпапка `raketa-admin-bot/` — админ-бот только для владельца: amo_sync (химчистка и уборки), carpets (Excel партнёра), gcal (два календаря), autocall (звонок по заявке с сайта). Базу рабочего бота админ-бот читает только на чтение (учётка `adminbot` имеет лишь SELECT), в amoCRM пишет своей интеграцией.

## Known Limitations

- **`recon/data/` содержит ПД клиентов и в git не попадает никогда** (папка в `.gitignore`, тексты разведки живут в `docs/recon/`).
- **`fetch_contact_leads` с фильтром `filter[contacts][id]` amoCRM молча игнорирует** (проверено 2026-08-25): возможно ложное «заказ уже оформлен». Отдельная задача.
- Проход отмен читает карточку каждого свежего ожидания раз в 10 минут: при десятках заказов вперёд это десятки запросов в CRM за проход. Поиск контакта по телефону — подстрочный `query` без пагинации (50 контактов), чужой контакт отсеивается по окончанию номера.
- **Прокси вне РФ — общая точка отказа трёх ботов**; откат: закомментировать `TELEGRAM_PROXY_URL` у рабочих ботов, `--telegram-proxy-off` у админ-бота. На VPS DNS для `api.telegram.org` отдаёт только нероутируемый IPv6: без прокси или `TELEGRAM_API_IPS` бот до Telegram не достучится. aiogram требует `aiohttp-socks` для любого прокси.
- Деплой ручной, SSH `admin@91.200.150.68`. Рабочий бот — `git pull` в `/opt/telegram-bot`; NOPASSWD покрывает `telegram-bot.service` и `raketa-admin-bot.service`, но **не** `telegram-bot-v2.service`. Админ-бот — два шага: rsync в `/home/admin/raketa-admin-bot`, затем `sudo raketa-admin-bot-update` (один `update` без rsync поднимает старую версию). Скрипт обновляется только при обычном запуске: новый ключ работает со второго вызова; `--leads`/`--stale`/`--report` службу не перезапускают.
- Переделки по гарантии робот не различает (решение владельца 2026-09-04), статус `owner_notified` глушит «нет». Путь к правилам уведомлений зашит в код (`bot.py`, `docs/notification_rules.json`), суточный лимит отправок — 60 на всю компанию.
- Клининг: «Расчётный» зачисляет в кассу сразу, метод «Карта» один общий, клинер не может отменить свой заказ. Живых уборок за всю историю 4, адрес в них вводится руками и в amoCRM не ходит. У клиента 1268 260 бонусов, начисленных руками, без срока сгорания.
- Autocall: робот звонит менеджеру на мобильный (`PBX_MANAGER_DIAL`); `contacted: true` — успех, событие перевода — клиент не взял, событий нет — менеджер не взял, нет записи за 5 минут — ветка менеджера by design. Отбивки не будет, звонок робота в карточку сделки не попадает (след пишет сам, одно примечание на цепочку). Репетиция держит состояние в памяти: боевой запуск начинается со своего включения.
- Сообщения владельцу показывают телефон целиком, в журналах маска до последних 4. Почта «ровно один раз» не обещает; при остановке админ-бота в журнале «Unclosed client session» (aiohttp) — шум завершения, не сбой.
- Два рантайма ботов делят `clients_db`. Тексты акций и дней рождения приходят из Google Sheet через внешний n8n. Токен опроса amoCRM долгоживущий: отзовут — опрос встанет молча. Вебхук Wahelp зависит от публичного входа (`hooks.crmfit.ru`, `dastydev.ru` на :8080).
- Тесты: корень — `.venv-wahelp/bin/python -m pytest tests/ -q` (307), pytest в окружении репозитория нет; админ-бот — `raketa-admin-bot/.venv/bin/python -m pytest -q` с `TEST_DB_DSN=postgresql://postgres@127.0.0.1:5432/adminbot_test` и `brew services start postgresql@14` (811 плюс 9 пропущено).
