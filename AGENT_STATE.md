## Purpose

Один репозиторий, две службы. Корень — рабочий бот клининговой компании (заказы, лояльность, зарплата, касса, уведомления, админка, обмен с amoCRM и письма клиенту). Подпапка `raketa-admin-bot/` — админ-бот только для владельца: amo_sync (химчистка и уборки), carpets (Excel партнёра), gcal (два календаря), autocall (звонок по заявке с сайта). Базу рабочего бота админ-бот читает только на чтение (учётка `adminbot` имеет лишь SELECT), в amoCRM пишет своей интеграцией.

## Known Limitations

- **Папка `robot_amo` — боевой вход**: файл партнёра до 100 строк робот проведёт и заведёт сделки с нуля. Перед запросом файлов предупреждать.
- **Переотправка клиенту вторым каналом идёт медленно**: по одному сообщению старше 10 минут, пауза 1–60 минут (решение владельца 16.09 — оставить).
- **Сообщения менеджеру по автозвонку идут без страховки**: токеном рабочего бота в личку, при обрыве теряются.
- **Бутстрап схем в коде создаёт таблицы с нуля, но не мигрирует существующие.** Миграции по существующим таблицам накатывать руками до рестарта службы: `cd /opt/telegram-bot && psql "$DB_DSN" -f app/migrations/<файл>.sql`.
- Репетиция уборок не проходит путь «новый клиент» до конца: он ждёт автосделку сейлзбота, которой в репетиции нет.
- API amoCRM v4 сделки не удаляет: лишнее удаляет владелец руками, робот только закрывает. Удалённую сделку API отдаёт пустым объектом без `id`, а не ошибкой.
- `recon/data/` и xlsx в корне содержат ПД и в git не попадают.
- Прокси вне РФ — общая точка отказа трёх ботов; резервные DNS с 15.09.
- Деплой ручной, SSH `admin@91.200.150.68`. Рабочий бот: `git pull --ff-only` в `/opt/telegram-bot`, миграции руками, затем рестарт. Админ-бот — два шага: `rsync` в `/home/admin/raketa-admin-bot`, затем `sudo raketa-admin-bot-update` (миграции он применяет сам). NOPASSWD не покрывает `sudo -u adminbot`, `sudo -u postgres` и `sudo cp`.
- Переделки по гарантии робот не различает; суточный лимит отправок 60 на компанию; клининг: «Расчётный» зачисляет в кассу сразу.
- Тесты: корень — `.venv-wahelp/bin/python -m pytest tests/ -q` (344 плюс 2 пропущено; с `TEST_DB_DSN=postgresql://postgres@127.0.0.1:5432/raketaclean_test` — 346); админ-бот — обязательно из его каталога: `cd raketa-admin-bot && TEST_DB_DSN=postgresql://postgres@127.0.0.1:5432/adminbot_test .venv/bin/python -m pytest -q` (872 плюс 9 пропущено).
