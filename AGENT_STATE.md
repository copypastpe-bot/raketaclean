## Known Limitations

- **Перезапуск `telegram-bot`** — по слову владельца; `sudo -n systemctl restart telegram-bot.service` у агента работает. FSM в памяти — перезапуск стирает. nginx — только владелец.
- **Служба оповещений: код обновляет только владелец** (`sudo rsync` агенту закрыт), `raketa-notify/docs/runbook.md` §8.
- **Выключатели админ-бота** — в его `.env`, обёрткой `sudo raketa-admin-bot-update --<ключ>`. **Рабочего бота** — `/opt/telegram-bot/switches.env` (владелец `admin`; без комментария в строке флага — `_env_int` его не срезает), список — `docs/deploy.md`.
- **База на проде:** `psql -d clients_db` как `admin` (peer): права на `public` выданы по таблицам — `promo_callbacks`, `order_close_reminders` агенту не видны. Миграции рабочего бота — от роли `bot` (`DB_DSN` из `.env`, не печатать) + строка в `schema_migrations` (`docs/deploy.md`). `psql -c` с несколькими запросами печатает только последний — по `-c` на запрос или `-f -`.
- **Тесты:** админ-бот — `TEST_DB_DSN=postgresql://postgres@127.0.0.1:5432/adminbot_test .venv/bin/python -m pytest -q`; рабочий бот — `…/raketaclean_test .venv-wahelp/bin/python -m pytest tests/ -q`; через `rtk` только `rtk proxy …`. `timeout` на маке нет.
- **Исполнителям:** запрет `stash`/`worktree`/`merge`/`push`; сверка HEAD первым шагом; одна задача на субагента; ревьюерам тесты запрещены. Субагент может зависнуть на обрыве связи — проверить дерево, прогнать тесты, возобновить его.
- **Деплой:** рабочий бот — пуш → `git pull --ff-only` в `/opt/telegram-bot` → миграции → перезапуск; админ-бот — `rsync` (с согласия владельца) → `sudo raketa-admin-bot-update`.
- Папка `robot_amo` — боевой вход ковров. Прокси вне РФ — общая точка отказа трёх ботов.
