## Known Limitations

- **Папка `robot_amo` — боевой вход**: файл партнёра до 100 строк робот проведёт и заведёт сделки с нуля (по замыслу). Перед запросом файлов предупреждать. Матчер берёт единственную открытую ковровую сделку клиента без учёта дат.
- **Переотправка клиенту вторым каналом идёт медленно**: проход берёт по одному сообщению без подтверждения доставки старше 10 минут и спит случайные 1–60 минут между ними (`bot.py`, защита от массовой рассылки; решение владельца 16.09 — оставить).
- **Сообщения менеджеру по автозвонку идут без страховки**: отправляются токеном рабочего бота в личку менеджера (@MrTo4ilka), при обрыве теряются; уведомления «начинаю звонить» не существует вовсе — только четыре сообщения о неудачах.
- Репетиция уборок не может пройти путь «новый клиент» до конца: он ждёт автосделку сейлзбота, которой в репетиции не будет; через 10 минут робот шлёт вопрос.
- API amoCRM v4 сделки не удаляет: лишнее удаляет владелец руками, робот только закрывает.
- `recon/data/` и xlsx в корне содержат ПД и в git не попадают (`.gitignore`).
- `fetch_contact_leads` с фильтром `filter[contacts][id]` amoCRM молча игнорирует; поиск контакта по телефону — подстрочный `query` без пагинации.
