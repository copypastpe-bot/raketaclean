## Known Limitations

- **Папка `robot_amo` — боевой вход**: фильтр почты кладёт туда любое письмо партнёра, робот проводит любой xlsx в течение часа. Перед запросом файлов у партнёра выключать ковры (`--carpets-off`). Матчер берёт единственную открытую ковровую сделку клиента без учёта дат: в архивном прогоне давал ложные пары на 4–12 месяцев.
- API amoCRM v4 сделки не удаляет: лишнее удаляет владелец руками, робот только закрывает.
- **`recon/data/` и xlsx в корне содержат ПД и в git не попадают** (`.gitignore`).
- `fetch_contact_leads` с фильтром `filter[contacts][id]` amoCRM молча игнорирует; поиск контакта по телефону — подстрочный `query` без пагинации.
- Проход отмен читает карточку каждого свежего ожидания раз в 10 минут: десятки запросов в CRM за проход.
- Прокси вне РФ — общая точка отказа трёх ботов; на VPS DNS для `api.telegram.org` отдаёт только нероутируемый IPv6. Провайдерский DNS 15.09 молчал 44 минуты (теперь есть резервные).
- Деплой ручной, SSH `admin@91.200.150.68`; NOPASSWD покрывает обе службы и `raketa-admin-bot-update` (с ключами `--report`, `--carpets-on/off` и др.), но не `sudo -u adminbot psql` и не правки системы. Админ-бот — два шага: rsync в `/home/admin/raketa-admin-bot`, затем `sudo raketa-admin-bot-update`.
- Переделки по гарантии робот не различает; суточный лимит отправок 60 на компанию; клининг: «Расчётный» зачисляет в кассу сразу, живых уборок 4.
- Autocall: звонит менеджеру на мобильный, отбивки нет, репетиция держит состояние в памяти. Сообщения владельцу с полным телефоном, в журналах маска.
- Тесты: корень — `.venv-wahelp/bin/python -m pytest tests/ -q` (307); админ-бот — `raketa-admin-bot/.venv/bin/python -m pytest -q` с `TEST_DB_DSN=postgresql://postgres@127.0.0.1:5432/adminbot_test` и `brew services start postgresql@14` (811 плюс 9 пропущено).
