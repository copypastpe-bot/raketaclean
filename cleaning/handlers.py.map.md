# Карта функций `cleaning/handlers.py`

2025 строк. Роутер aiogram со всеми диалогами клининга: проведение уборки,
касса, выплата прибыли, отмена. Подключается в `bot.py` через
`dp.include_router(cleaning_router)`.

Как читать: почти всё здесь — шаги пошаговых диалогов (FSM). Один диалог —
это цепочка «старт → вопрос → вопрос → подтверждение → проведение»; деньги
пишутся только на последнем шаге, внутри одной транзакции.

Осторожно: заглушка «команда не распознана» в `bot.py` ловит текст раньше
этого роутера, поэтому каждая новая текстовая кнопка бригадира не работает,
пока её не впишут в мост (известное ограничение, `AGENT_STATE.md`).
Внутри шага диалога (FSM) заглушка не мешает — у неё `StateFilter(None)`;
проверено через настоящий диспетчер в `tests/test_cleaning_olya_choice.py`.
Команды (текст с «/») заглушка не ловит вовсе — проверено для `/cleaning_olya`
в `tests/test_cleaning_olya_view.py`.

## Шаг «Оля / Дима» (из чьих денег операция)

Админские операции с кассой спрашивают, чьи деньги: «Оля» — деньги компании на
руках у Оли (`cash_holder='olya'`), «Дима» — обычная касса (`'dima'`). Шаг идёт
после суммы, до комментария (у выплаты — до подтверждения), в пяти сценариях:
приход, расход, изъятие, выплата прибыли и расход бригадира, если его ведёт не
клинер. Тексты вопросов — константы `CASH_HOLDER_QUESTION_SPEND` /
`CASH_HOLDER_QUESTION_INCOME`. Строка «Деньги Ольга: N₽» в чат — только при «Оля».

| Строка | Функция | Назначение |
|---|---|---|
| 225 | `_cash_holder_kb` | кнопки «Оля» / «Дима» / «Отмена» (как `expense_owner_kb` в `bot.py`) |
| 236 | `_parse_cash_holder` | ответ → `olya` / `dima` / None |
| 241 | `_cash_holder_line` | строка подтверждения: «Источник: деньги Ольга» / «Источник: касса (Дима)»; у прихода «Куда: …» |
| 247 | `_ask_cash_holder` | задать вопрос «Источник?» (у прихода «Куда вносим?») |
| 254 | `_reask_cash_holder` | ответ не «Оля»/«Дима» — переспросить |

## Перемещение между кучками (`CleaningCashMoveFSM`)

«Деньги Ольга» ↔ «Касса (Дима)», вся касса клининга не меняется (ТЗ
`docs/plans/2026-10-05-olya-money-move.md`, задача 3). Запись и остатки — в
`admin_ops.record_cash_move` / `cashbook.get_holder_balance`; остаток источника
проверяется на шаге суммы и ещё раз под замком при записи.

| Строка | Функция | Назначение |
|---|---|---|
| 1668 | `_cash_move_source_kb` | кнопки «Деньги Ольга» / «Касса (Дима)» / «Отмена» (подписи из констант); ответ → код кучки по `_CASH_MOVE_SOURCES` |
| 1681 | `_cash_move_exceeds_text` | «Нельзя больше остатка: в «…» N₽.» — шаг суммы и отказ на «Провести» |
| 1686 | `start_cash_move` | `/cleaning_move` (право `cleaning_manage_cash`) — «Откуда перемещаем?» |
| 1697 | `cash_move_source` | источник; остаток ≤ 0 — «перемещать нечего», сценарий закрыт; иначе маршрут и остаток, спросить сумму |
| 1727 | `cash_move_amount` | сумма; остаток перечитывается, больше остатка — отказ и сумма снова |

## Удаление перемещения (`CleaningCashMoveDeleteFSM`)

По образцу `/cleaning_dividend_cancel` (ТЗ `docs/plans/2026-10-05-olya-money-move.md`,
задача 4). Удаление проверяется на шаге подтверждения
(`admin_ops.check_cash_move_delete`) и ещё раз под замком при «Провести»
(`admin_ops.delete_cash_move`). Номер больше `_PG_INT4_MAX` (id — integer)
до базы не доходит, ответ — «не найдено».

| Строка | Функция | Назначение |
|---|---|---|
| 1814 | `_cash_move_not_found_text` | «Перемещение #N не найдено или уже удалено.» |
| 1818 | `_cash_move_goes_negative_text` | «Нельзя: в «…» станет -N₽.» — шаг подтверждения и отказ на «Провести» |
| 1823 | `start_cash_move_delete` | `/cleaning_move_delete [N]` (право `cleaning_manage_cash`): без номера — 10 последних перемещений; с номером — проверка и «Удалить перемещение #N?» с маршрутом и суммой |
| 1873 | `cash_move_delete_provesti` | удаление (`delete_cash_move`) и остатки двух кучек в одной транзакции; не найдено или минус — ответ, ничего не изменено; успех — сообщение в чат (`format_cash_move_delete_alert`) и «Перемещение #N удалено.» |
