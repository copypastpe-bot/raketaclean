## Что экзамен нашёл и что было исправлено

1. **amoCRM молча игнорирует фильтр `filter[contacts][id]`** и отдаёт все сделки аккаунта
   подряд (проверено: 250 чужих сделок, ни одной своей). Клиент листал их страницами,
   пока не исчерпал память. Исправлено: сделки клиента берём из самого контакта
   (`contacts?query=<телефон>&with=leads`), затем пакетом по `filter[id][]`.
   Тот же дефект есть в рабочем боте — `tgbot-v1/bot.py:1534`, влияет на алерты
   «клиенту не ответили»: они могут указывать на чужую сделку.
2. **Заказ №421**: «Дата и время заказа» в сделке не совпадает с датой заказа →
   робот создал бы дубль. Добавлен запасной признак — дата закрытия сделки (±3 дня).
3. **Заказы №497, №508**: забытые открытые сделки постоянного клиента (с 2025 года)
   перехватывали решение и уводили в вопрос. Проверка «не проведён ли заказ руками»
   перенесена ДО разбора открытых сделок без дат.

## Как считалось

«Факт» — сделка воронки реализации на успешном этапе, найденная сначала по полю
«Дата и время заказа» (±2 дня), затем по дате закрытия сделки (±3 дня).
Телефоны маскированы до последних 4 цифр. Воспроизведение:

```
python -m scripts.history_exam --days 90 \
  --bot-env /opt/telegram-bot/.env --amo-env /opt/telegram-bot/.env
```
