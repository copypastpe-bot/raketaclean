# ТЗ: отмена по календарю закрывает задачи и ставит «Причину закрытия»

Дата: 2026-09-10. Автор задачи: владелец. Проект: `raketa-admin-bot`, функция gcal.
Парное ТЗ для рабочего бота: `docs/plans/2026-09-10-cancel-letter-to-client.md`
(письмо клиенту; исполняется из сессии `tgbot-v1`).

## Зачем (в двух словах)

Когда владелец удаляет запись из календаря и на карточке робота нажимает
«🔒 Закрыть сделку», робот переводит сделку в «Закрыто и не реализовано» и
оставляет примечание. Владелец хочет, чтобы в этот же момент робот:

1. закрыл открытые задачи этой сделки (сейчас они висят и требуют внимания);
2. заполнил поле сделки «Причина закрытия» значением «Пропала потребность».

Пункт 2 заодно становится сигналом для рабочего бота: увидев закрытую сделку
с этой причиной, он напишет клиенту «заказ отменён» (парное ТЗ). Общий язык
двух роботов — только карточка амо, как с галочкой «веду сам».

## Решения владельца (2026-09-10)

- Задачи закрываем все открытые у закрываемой сделки, с результатом
  «🤖 Заказ отменён: запись удалена из календаря».
- Трогаем только закрываемую сделку (`real_lead_id or primary_lead_id`,
  как сейчас в `_close_deal`). Первичный лид не трогаем: к этому моменту он
  уже «Передан в работу».
- Порядок «спросить владельца → закрыть по кнопке» не меняется (решение 2 от
  2026-08-26: удаление бывает и переносом, и случайностью).
- Отдельного выключателя нет: действие происходит только по нажатию владельца.

## Что уже выяснено — не перепроверять

1. Точка входа: `adminbot/gcal/engine.py`, `_close_deal` (строка ~250).
   Вызывается из `process`, когда `link.status == "closing"` — это статус,
   который ставит Telegram-обработчик по кнопке «🔒 Закрыть сделку»
   (`adminbot/tg/bot.py:285`). Сейчас: `store.log(move_lead)` →
   `amo.move_lead(lead, pipeline, STATUS_CLOSED)` → `amo.add_note(...)` →
   `store.update(status="cancelled", skip_reason=...)`.
2. Ветка «сделка уже закрыта руками» в `_close_deal` есть — её не трогать:
   ни задач, ни причины по чужому закрытию не ставим.
3. Поле «Причина закрытия» — кастомное поле сделки, тип select,
   `id = 19215`. Значение «Пропала потребность» — `enum_id = 8299`
   (справочник `tgbot-v1/recon/data/amocrm_leads_custom_fields.json` от
   2026-08-25). Встроенные «причины отказа» амо в аккаунте ВЫКЛЮЧЕНЫ
   (`is_loss_reason_enabled = false`), `loss_reason_id` не использовать.
   Перед деплоем сверить id вживую: `scripts/show_field_enums.py` (на VPS,
   амо с локальной машины недоступна).
4. Задачи сделки: `AmoClient.get_lead_tasks(lead_id)` отдаёт открытые задачи,
   `AmoClient.complete_task(task_id, result_text)` закрывает одну.
   Образец использования — `adminbot/sync/engine.py`, `_close_tasks` (там
   фильтр по типам задач; здесь фильтра нет — закрываем все открытые).
5. Поле-select пишется через `adminbot.amo.fields.enum_field(field_id, enum_id)`
   и `AmoClient.update_lead(lead_id, custom_fields=[...])`.
6. Правило «заполненное не трогаем» у робота действует для «Услуги» и «Адреса».
   Для «Причины закрытия» — так же: если у открытой сделки поле уже заполнено
   человеком, не перезаписывать (допущение агента; владелец не возражал).
7. Журнал действий: каждое обращение к амо в gcal предваряется
   `store.log(event_id, action, dry_run=..., entity=..., amo_id=..., payload=...)`
   — повторить для `complete_task` и `update_lead`. Репетиция (`dry_run`)
   устроена через клиент амо и журнал, отдельной ветки в `_close_deal` нет.

## Что сделать

### 1. `adminbot/amo/ids.py`

Добавить рядом с полями сделки:

```python
FIELD_CLOSE_REASON = 19215          # Причина закрытия (select) — своё поле владельца
CLOSE_REASON_ENUM_NO_NEED = 8299    # «Пропала потребность»
```

### 2. `adminbot/gcal/engine.py`, `_close_deal`

Новый порядок после проверки «уже закрыта»:

1. Открытые задачи: `get_lead_tasks(lead_id)` → для каждой
   `store.log(..., "complete_task", entity="task", amo_id=task_id)` и
   `complete_task(task_id, CANCEL_TASK_RESULT)`. Константа
   `CANCEL_TASK_RESULT = "🤖 Заказ отменён: запись удалена из календаря"`.
2. Причина: если `field_value(lead, FIELD_CLOSE_REASON)` пусто —
   `store.log(..., "update_lead", payload={"field": FIELD_CLOSE_REASON})` и
   `update_lead(lead_id, custom_fields=[enum_field(FIELD_CLOSE_REASON,
   CLOSE_REASON_ENUM_NO_NEED)])`. Заполнено — пропустить, в примечании
   написать «причина оставлена как была».
3. Перевод в «Закрыто и не реализовано» — как сейчас.
4. Примечание — дополнить: «Закрыто задач: N. Причина: Пропала потребность.»
5. `store.update(status="cancelled", ...)` — как сейчас.

Причину ставить ДО перевода в закрытый статус: так порядок совпадает с тем,
как поля заполняет человек, и закрытие остаётся последним необратимым шагом.

Сбой на шаге 1–2 (сеть, ошибка амо) — не глотать: исключение уходит наверх,
как у прочих обращений `process` (запись получит `status="error"`, следующий
проход повторит с начала; закрытые задачи повторно закрывать безопасно —
`get_lead_tasks` их уже не вернёт).

### 3. Тесты — `tests/test_gcal_engine.py`

Рядом с существующим тестом закрытия (`status="closing"`, строка ~272):

- закрывает все открытые задачи, у каждой result-текст `CANCEL_TASK_RESULT`;
- ставит `FIELD_CLOSE_REASON = 8299` через `update_lead`;
- поле уже заполнено → `update_lead` не вызывается;
- задач нет → `complete_task` не вызывается, остальное как прежде;
- сделка уже закрыта руками → ни задач, ни причины, ни перевода (существующее
  поведение, убедиться тестом);
- в журнале `gcal_actions` есть записи `complete_task` и `update_lead`.

Фейк амо в тестах должен уметь `get_lead_tasks`/`complete_task`/`update_lead`
с записью вызовов — если у существующего фейка их нет, добавить.
