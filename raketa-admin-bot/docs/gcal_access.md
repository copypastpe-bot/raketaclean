# Доступ робота к календарю: что нужно сделать владельцу

Роботу нужен собственный ключ к календарю `raketaclean52@gmail.com`. Ваш личный
доступ для этого не подходит: робот работает на сервере круглосуточно, а вход от
имени человека Google периодически отзывает — робот молча ослепнет.

Правильный способ — **служебный аккаунт**: технический «сотрудник» Google без
почты и пароля, у которого есть только ключ-файл. Ключ не протухает, и после
настройки от вас больше ничего не требуется.

Времени: около десяти минут, один раз. Всё бесплатно — Calendar API денег не стоит.

## Шаг 1. Создать проект

1. Откройте [console.cloud.google.com](https://console.cloud.google.com) под аккаунтом,
   у которого есть доступ к календарю компании.
2. Вверху слева — выпадающий список проектов → **Новый проект**.
3. Название: `raketa-robot`. Нажмите **Создать** и дождитесь, пока он появится
   в списке (10–20 секунд), затем выберите его.

## Шаг 2. Включить Calendar API

1. Слева: **API и сервисы → Библиотека**.
2. В поиске наберите `Google Calendar API`, откройте его.
3. Нажмите **Включить**.

Если пропустить этот шаг, робот получит отказ «Calendar API не включён» —
проверка на шаге 6 это покажет.

## Шаг 3. Завести служебный аккаунт

1. Слева: **API и сервисы → Учётные данные**.
2. Вверху: **Создать учётные данные → Сервисный аккаунт**.
3. Имя: `raketa-calendar-reader`. Нажмите **Создать и продолжить**, затем
   **Готово** (роли и доступы на этих экранах не нужны).
4. В списке появится адрес вида
   `raketa-calendar-reader@raketa-robot.iam.gserviceaccount.com` — **скопируйте его**,
   он понадобится на шаге 5.

## Шаг 4. Скачать ключ

1. Нажмите на созданный аккаунт → вкладка **Ключи**.
2. **Добавить ключ → Создать ключ → JSON → Создать**.
3. Браузер скачает файл вида `raketa-robot-xxxxx.json`. Это и есть ключ.

**Ключ — как пароль.** Не пересылайте его почтой и мессенджерами, не кладите в
общие папки. Один файл, один раз, прямо на сервер (шаг 6).

## Шаг 5. Дать роботу читать календарь

1. Откройте [calendar.google.com](https://calendar.google.com) под аккаунтом
   `raketaclean52@gmail.com`.
2. Слева в списке календарей наведите на нужный → три точки → **Настройки и доступ**.
3. Раздел **Доступ отдельным пользователям** → **Добавить пользователей**.
4. Вставьте адрес служебного аккаунта из шага 3.
5. Права: **«Просмотр всех сведений о мероприятиях»**.
   Не «Изменение мероприятий» — роботу писать в календарь незачем, а лишние права
   когда-нибудь обернутся случайной правкой.
6. **Отправить**. Приглашение уходит служебному аккаунту и принимается само —
   подтверждать ничего не нужно.

## Шаг 6. Положить ключ на сервер и проверить

Ключ кладётся в домашнюю папку `admin` под именем `.gcal.json`. С вашего
компьютера, из папки со скачанным файлом:

```bash
scp raketa-robot-xxxxx.json admin@91.200.150.68:~/.gcal.json
ssh admin@91.200.150.68 'chmod 600 ~/.gcal.json'
```

Дальше — обычная команда обновления: она перенесёт ключ службе и проверит доступ.

```bash
sudo raketa-admin-bot-update --gcal-check
```

Робот прочитает календарь и покажет ближайшие записи: что он считает заказом,
какую услугу и район распознал, нашёлся ли телефон. **В amoCRM при этом не уходит
ничего** — это только проверка глазами.

## Шаг 7. Включение

Порядок тот же, что был у заказов и ковров: сначала репетиция, потом бой.

```bash
# 1–2 дня: робот решает, но в CRM ничего не пишет; решения приходят в Telegram
sudo raketa-admin-bot-update --gcal-on --gcal-rehearsal

# когда решения устраивают — боевой режим
sudo raketa-admin-bot-update --gcal-live
```

Проверить состояние в любой момент: команда `/status` в боте, а `/calendar` —
посмотреть календарь прямо сейчас, не дожидаясь очередного обмена.

Выключить, если что-то пойдёт не так:

```bash
sudo raketa-admin-bot-update --gcal-off
```

Уборка и ковры при этом продолжают работать: у каждой функции свой выключатель.

## Что робот будет делать после включения

- **Берёт в работу только записи, появившиеся после включения.** Те, что уже лежат
  в календаре (в том числе заказы постоянных клиентов на три недели вперёд), он
  запомнит, но трогать не станет — их вы ведёте сами.
- По новой записи находит лид в амо (или заводит), заполняет услугу, дату, адрес,
  комментарий и район, передаёт в работу и останавливается на «Заказ оформлен».
  Мастера и сумму чека проставит позже — когда мастер закроет заказ в боте.
- **Удалённая запись** = отменённый заказ: робот пришлёт карточку с кнопками.
  Сам сделку не закрывает.
- Выходные мастеров («⛔️…»), перемывы по гарантии и записи без телефона пропускает
  молча. Теплоход предложит завести кнопкой.

## Как добавить ещё один календарь

Календарей у робота может быть несколько: мебель и ковры ведут мастера в основном,
уборки — бригадир в своём. Порядок такой:

1. **Дать доступ** — шаг 5 этой инструкции, но для нового календаря: тот же адрес
   служебного аккаунта, те же права «Просмотр всех сведений о мероприятиях».
2. **Узнать адрес календаря**: три точки у календаря → «Настройки и доступ» →
   раздел «Интеграция календаря» → строка **«Идентификатор календаря»**.
   У созданного вручную он длинный, вида `…@group.calendar.google.com`.
3. **Добавить его в настройки службы** (`/opt/raketa-admin-bot/.env`), через запятую
   к уже указанному, **без пробелов**:

   ```text
   GCAL_CALENDAR_ID=raketaclean52@gmail.com,ДЛИННЫЙ_АДРЕС@group.calendar.google.com
   ```

   Пробел внутри строки сломает перенос настроек в службу — она читает их
   построчно. Первым оставьте основной календарь: ему принадлежит закладка
   обмена, накопленная до появления второго.
4. **Проверить**: `sudo raketa-admin-bot-update --gcal-check` — робот покажет
   ближайшие записи каждого календаря отдельным разделом. В amoCRM ничего не уходит.

Дальше робот работает с новым календарём так же, как с основным. **Записи,
лежавшие в нём до подключения, он не трогает** — они остаются вашими. Если
какую-то из них всё же нужно провести, назовите её явно:

```bash
sudo raketa-admin-bot-update --gcal-run=<идентификатор записи>
```

Идентификатор записи виден в выводе `--gcal-check` в квадратных скобках.

## Если что-то не работает

| Что видно | Что случилось | Что делать |
|---|---|---|
| «Файл ключа не найден» | ключ не доехал на сервер | повторить `scp` из шага 6 |
| «Calendar API не включён» | пропущен шаг 2 | включить API и повторить проверку |
| «Доступ к календарю не работает» | не выполнен шаг 5 или дан не тот адрес | проверить, что доступ выдан адресу служебного аккаунта |
| Робот молчит, записей нет | функция выключена | `sudo raketa-admin-bot-update --gcal-on` |
