владельца — не термины из кода: «проведено», «ждут вашего ответа», а не
статусы из базы.

## Вечерняя сводка (ТЗ 2026-09-21-evening-summary-rework.md)

Числа и хвосты — две независимые части, которые строит `summary_text`
раздельными функциями (`_numbers_block`, `_tails_block`) и только склеивает —
задача 4: когда потоки переедут на шину оповещений, резать нужно будет по
этому шву. Заказы и уборки в хвостах идут одним общим списком без разделения
по потоку (задача 3, решение владельца 21.09), а в числах — раздельно
(задача 2/4).

| Строка | Имя | Назначение |
|---|---|---|
| 233–241 | `_TAIL_CATEGORIES` (константа) | четыре категории хвостов и их подписи, в порядке утверждённого макета |
| 241 | `TAIL_CAP` (константа) | не больше позиций в категории, дальше «…и ещё N» (умолчание координатора 21.09) |
| 247 | `CALENDAR_FAILURE_LINE` (константа) | задача 9: текст строки о сбое календарного прохода в хвостах |
| 250 | `summary_text` | собрать сообщение вечерней сводки целиком: заголовок → числа → уборки → хвосты |
| 293 | `_numbers_block` | четыре числа «что сделал робот» за сутки (задачи 2, 4, 8); «Событий не было.», если все нули |
| 309 | `_tails_block` | блок хвостов: строка о сбое календаря (задача 9) + четыре категории заказов и уборок вместе |
| 329 | `_tail_rows` | строки одной категории: номер, телефон, дата, ссылка на сделку; у сбоя ещё текст ошибки |
| 363 | `_lead_ref` | номер сделки в строке хвоста — `#<номер>`, а с известным `base_url` кликабельная ссылка (задача 5) |
