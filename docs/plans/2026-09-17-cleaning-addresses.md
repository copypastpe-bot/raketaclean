# ТЗ — адреса в клининге (уборки)

Дата: 2026-09-17
Основание: бриф `docs/plans/2026-09-16-brief-cleaning-tail.md`, решения владельца 17.09
Затрагивает: рабочий бот — модуль `cleaning/`, `bot.py`, `app/migrations/`
Предшественник: `docs/plans/2026-09-16-addresses.md` (химчистка, 10 задач, сделано)

## Зачем

16.09 адрес перестали спрашивать у мастера в химчистке: он приезжает из amoCRM сам.
Контур уборок остался по-старому — бригадир вводит адрес руками, а сообщение о деньгах
уходит в момент проведения, не дожидаясь адреса. Эта работа доводит уборки до того же
устройства.

## Решения владельца 17.09

1. **Адрес у бригадира убираем совсем.** Вместо него — необязательное поле
   «комментарий» с подсказкой вида «Введите комментарий, например адрес».
2. **Комментарий идёт в чат кассы клининга и в базу.** В amoCRM он не уходит.
3. **Уборка вне календаря** ведёт себя как заказ химчистки: админ-бот заводит сделку
   с нуля и присылает владельцу карточку «сделка без адреса» с кнопками.
4. Работу **исполняем сразу**, не дожидаясь живой проверки химчистки (решение 17.09,
   отменяет условие брифа).

Устройство, подтверждённое владельцем: **адрес — из CRM, комментарий — от бригадира**.
Колонка `address` остаётся и заполняется роботом; `comment` — новая, её пишет человек.

## Что уже работает для уборок (проверено, не переделывать)

- колонка `deal_address` есть в `adminbot.cleaning_links`, админ-бот пишет туда адрес
  сделки — и при обычном заполнении, и на пути «уже сделано»;
- фоновый проход рабочего бота `_backfill_address_for_table` (`bot.py:7052`) уже читает
  `public.cleaning_orders` и `adminbot.cleaning_links`; условие выборки —
  `(o.address IS NULL OR o.address = '')`, то есть **после снятия `NOT NULL` он
  подхватит уборки сам**, править его не нужно;
- карточка «сделка без адреса» с кнопками и напоминаниями работает для уборок наравне
  с заказами.

## Задача 1. Диалог бригадира: адрес убрать, комментарий добавить

**Миграция** в `app/migrations/` (следующий свободный номер, сейчас последний — `0009`):

```sql
ALTER TABLE cleaning_orders ALTER COLUMN address DROP NOT NULL;
ALTER TABLE cleaning_orders ADD COLUMN IF NOT EXISTS comment text;
```

Снятие `NOT NULL` обязательно: без него уборка перестанет проводиться, как только
исчезнет вопрос бригадиру.

**Код** (`cleaning/fsm.py`, `cleaning/handlers.py`):

1. Из `CleaningOrderFSM` убрать состояния `address_choice` и `address`; удалить
   хендлеры диалога адреса (`cleaning/handlers.py:326–383`) и клавиатуру
   `_address_choice_kb` (`:144`).
2. Добавить состояние `comment` **на то же место в цепочке**, где стоял адрес.
   Текст вопроса: «Введите комментарий, например адрес» плюс кнопка «Без комментария».
   Образец такого диалога в проекте уже есть — расход бригадира,
   `cleaning/handlers.py:875–888`; сделать по нему, включая обработку пустого ввода.
3. Комментарий необязательный: «Без комментария» или пустой ввод — пишем NULL,
   диалог идёт дальше.
4. Адрес при проведении **не заполняется вовсе** — его позже допишет фоновый проход.

**Проверка:** уборка проводится без единого вопроса про адрес; в базе `address` пуст,
`comment` содержит введённое или NULL.

Выполнено: ✔

Пустой комментарий строку не добавляет: лишних пустых строк в сообщении быть не должно.

## Задача 3. Сообщение о проведённой уборке ждёт связки

Сегодня оно уходит сразу: `cleaning/handlers.py:774`, `send_cleaning_money_flow`.

Сделать как у химчистки (задача 5 ТЗ от 16.09): при проведении уборки сообщение
**ставится в очередь**, а уходит, когда у уборки появилась связка в
`adminbot.cleaning_links` — с адресом или без. Предохранитель — 30 минут.

**Очередь переиспользовать**, а не заводить вторую: `pending_order_reports`
(`app/migrations/0009_pending_order_reports.sql`) и цикл `run_pending_order_reports`
(`bot.py`). Уборки отличаются таблицей связок и чатом назначения — учесть это в очереди
явным признаком контура, а не догадкой по номеру заказа: **номера уборок и заказов
пересекаются**, заказ №5 и уборка №5 существуют одновременно.

**Деньги в кассу клининга пишутся сразу и ничего не ждут** — эту часть не трогать.

**ВНИМАНИЕ.** У `send_cleaning_money_flow` есть второй вызов —
`cleaning/handlers.py:913`, это **расход бригадира**, к заказам отношения не имеет.
Его не трогать.

**Проверка:** тесты на три случая — связка с адресом, связка без адреса, связки нет
вовсе (уход по предохранителю).

Выполнено: ☐

## Задача 4. Сигналы в чат ошибок для уборок

Задача 6 ТЗ от 16.09 сделала два сигнала только для химчистки. Повторить для уборок,
теми же текстами, с пометкой, что речь об уборке:

1. **«Сделка создана без адреса»** — админ-бот завёл сделку с нуля (`path='C'`), адреса
   в ней нет. Телефон клиента — **полный, не маскированный** (решение владельца 16.09).
2. **«Админ-бот не ответил за 30 минут»** — связка не появилась вовсе.

Адресат — `LOGS_CHAT_ID`, как у химчистки (до ревизии чатов, которую владелец сделает
отдельно).

Выполнено: ☐

## Задача 5. Пустой адрес в сообщениях об уборке

Решение владельца 17.09: **отчёты по удалённым заказам гасить не надо** — чат кассы
это журнал, сообщение пусть приходит. Сообщение об отмене с итоговой кассой уже
работает в обоих контурах (`cleaning/handlers.py:1406`, `format_cancel_order_alert`),
переделывать нечего.

Но после этой работы адрес уборки в момент проведения **пуст**, а сообщения печатают
его безусловно — `cleaning/format.py:153`, строка `f"Адрес: {address}"`, параметр
объявлен как `str`. С пустым адресом в чат придёт «Адрес: None».

Сделать: во всех сообщениях контура уборок пустой адрес строку **не добавляет** —
ровно так же, как пустой комментарий из задачи 2. Пройти по `cleaning/format.py`
и проверить каждое место, где печатается адрес: проведение, отмена, карточка клиента,
отчёты кассы.

**Проверка:** тесты на сообщения с пустым адресом — строки «Адрес» в них нет,
«None» не появляется нигде.

Выполнено: ☐

## Задача 6. Сквозная проверка контура уборок

Правок не требует, только тесты — убедиться, что цепочка собирается целиком:

1. уборка проводится без вопроса про адрес, адрес в базе пуст;
2. админ-бот записал адрес сделки в `cleaning_links`;
3. фоновый проход дозаполнил `cleaning_orders.address`, `clients.address`
   и `clients.last_order_addr`;
4. сообщение в чат кассы клининга ушло после появления связки и содержит адрес
   и комментарий.
