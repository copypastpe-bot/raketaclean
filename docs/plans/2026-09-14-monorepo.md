## Зачем (для владельца)

Два бота, рабочий (`tgbot-v1`) и админский (`raketa-admin-bot`), связаны через
амо: сигнал ставит один, читает другой. Сегодня это два репозитория, две памяти
и постоянные прыжки между проектами. После этой задачи будет один репозиторий
`raketaclean` с одним контекстом, а на сервере по-прежнему две службы.

## Решения владельца 2026-09-14 (не обсуждаются)

1. Раскладка: рабочий бот остаётся в корне без изменений, админ-бот переезжает
   в подпапку `raketa-admin-bot/` со всей своей историей git.
2. Ветки: `main` в обоих репозиториях подтягивается до боевых веток
   (`feature/amo-exchange` = `a9a4fab` плюс коммит с этим ТЗ, `feature/amo-sync-v1` = `dc49552`),
   монорепозиторий собирается на `main`, сервер рабочего бота переключается
   на `main` при деплое.
3. Тексты разведки `recon/*.md` переезжают в `docs/recon/`.
4. Контекст один: папка `project_ai_context/raketaclean/` в `agent1`, один
   `AGENT_STATE.md`, один `SESSION_LOG.md`; заметки агента обоих проектов
   сливаются. Корневой `CLAUDE.md` с общими правилами плюс
   `raketa-admin-bot/CLAUDE.md` со своими.
5. Репозиторий и папка переименовываются в `raketaclean`.
6. Бриф 11.09 отправлен на GitHub координатором до начала работ (сделано).
