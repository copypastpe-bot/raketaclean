# ТЗ: сторож проведения заказов — запись в календаре есть, заказа в боте нет

Дата: 2026-10-13. Решения владельца — в разговоре 13.10, перечислены ниже.
Рабочий бот (корень репозитория). Админ-бот не трогаем.

Базовый коммит: SHA из промпта.

## Зачем

Мастера не всегда проводят заказ в боте. Разбор 13.10 за 14 дней: 39 записей-заказов в календаре
с прошедшей датой; 31 проведены с привязкой к записи; 1 проведён по второму номеру записи без
привязки (Лора, 29.09, заказ #670); 2 — заказы клининга; 5 не найдены. Из пяти: Лора — ложная
(второй номер), кафе «Хюгге» — проведено через неделю (13.10, #704), Валерия — висит,
Валерий ×2 — работы ещё идут.

## Решения владельца (13.10)

1. Сообщение — в **два чата**: «Заказы подтверждения» (`ORDERS_CONFIRM_CHAT_ID`) и
   «Ракета чат сотрудников» (номер владельца: 2534573111 — точный id группы координатор
   впишет в `switches.env` при выкате).
2. **Первое напоминание** — на следующий день после даты в календаре, **с 10:00 МСК**;
   **повтор каждые 30 минут до 20:00**, ночью молчит.
3. **Кнопка «Напомнить завтра»**: нажали — до 10:00 следующего дня тишина; завтра заказ всё
   ещё не проведён — напоминание снова (с теми же повторами). Не нажали — повтор через 30 минут.
4. **Текст** — без телефона клиента и без фразы про календарь:

   ```
   ⚠️ Заказ не проведён в боте
   04.10 · Валерий · Афонино, Восточная, 342
   Ковры, мебель

   Проведите заказ в боте.
   [ Напомнить завтра ]
   ```

Решения координатора (владелец утвердил план 13.10):

- По каждому заказу — своё сообщение со своей кнопкой.
- Повтор через 30 минут: **прежнее напоминание удаляется, отправляется новое** (люди снова
  получают уведомление, чат не засоряется).
- «Напомнить завтра» в любом из двух чатов → сообщение **в обоих** меняется на
  «Отложено до завтра — <кто нажал>» (без кнопки).
- Заказ провели → последнее напоминание меняется на «✅ Заказ проведён» (без кнопки), робот
  замолкает.
- При запуске — 14 дней назад (см. «Кандидаты»).
- Выключатель `ORDER_CLOSE_REMINDER_ENABLED` (`switches.env`), **по умолчанию выключен**;
  второй чат — `STAFF_CHAT_ID` (`switches.env`), 0 — не слать туда.

## Устройство (решение координатора; факты — по коду на `4329ffa`)

**Образец — карточки «Неразобранное»**, всё то же самое, только про заказы:
таблица — `app/migrations/0014_amocrm_unsorted_cards.sql`; правила времени —
`notifications/amocrm_unsorted.py` (`_align_to_window`, `next_reminder_at`, окно 9–20);
рассылка — `run_unsorted_cards_dispatch` / `_unsorted_card_send_due` (`bot.py:~2843–2900`);
кнопка — `unsorted_card_done_cb` (`bot.py:~2916`, **регистрируется раньше обработчиков по
состоянию** — комментарий там же объясняет почему; сделай так же); запуск —
`schedule_periodic_job` (`bot.py:~14281`). Повторяй устройство, отличия — ниже.

**Записи календаря** — представление `adminbot.calendar_jobs`
(`raketa-admin-bot/migrations/015_calendar_jobs.sql`; роль `bot` имеет `SELECT`): `event_id`,
`phone10`, `phones` (все номера записи), `order_date`, `client_name`, `address`, `services`,
`status`, `order_id`; там только `kind='order'` и статусы `done/in_progress/waiting_salesbot`
(удалённые/отменённые записи из него пропадают). Колонки представления не менять.

**«Проведён»** — любое из (окно — с `order_date − 1 день` и без верхней границы: кафе провели
через неделю):
- в `orders` есть строка с `calendar_event_id = event_id`;
- в `orders` есть строка, где последние 10 цифр `phone_digits` — любой из `phones` записи;
- в `cleaning_orders` (не `deleted_at`) есть строка клиента (`clients.phone_digits`, последние
  10 цифр) с любым из `phones`; дата — `coalesce(happened_at, created_at)`.

**Кандидаты** — записи из `calendar_jobs` с `order_date` от `сегодня − 14` до `вчера` (МСК),
не проведённые, **плюс** все записи, по которым уже есть открытое напоминание (любой давности —
напоминаем, пока не проведут или не уберут из календаря). Запись пропала из
`calendar_jobs` (удалили, отменили) → последнее напоминание удалить, строку закрыть, молча.

**Таблица** — новая миграция `app/migrations/0018_order_close_reminders.sql` (по образцу
0014; применяет координатор при выкате по `docs/deploy.md`): `event_id` (ключ), дата
записи, статус (`open` / `closed` — проведён / `gone` — пропала из календаря), `next_send_at`,
номера последних сообщений по чатам (`chat_id` + `message_id`), кто и когда нажал «Напомнить
завтра», отметки времени. Состав колонок — на твоё усмотрение, обоснуй.

**Время** — чистые функции в новом модуле `notifications/order_close_reminder.py`: первое
напоминание — `order_date + 1 день, 10:00 МСК` (раньше — нельзя; позже 10:00 — сразу, но в окне);
повтор — `+30 минут`; окно `[10:00, 20:00)` МСК, всё вне окна сдвигается на ближайшие 10:00;
«Напомнить завтра» — `10:00 следующего дня`. Там же — текст сообщения и названия услуг:
`furniture` — мебель, `mattress` — матрас, `cleaning` — клининг, `carpeting` — ковры,
`rug_home` — ковёр на дому, `windows` — окна; незнакомый код — как есть. Порядок услуг —
как в записи, первая с большой буквы. Имя и адрес — как в записи; пустые — пропустить.
Текст без `parse_mode` (или с экранированием HTML: в именах и адресах бывают `<`, `>`, `&`).

**Рассылка** — периодическая задача (раз в 5 минут, своё имя), только при
`ORDER_CLOSE_REMINDER_ENABLED`: обновить кандидатов; закрыть проведённые («✅ Заказ
проведён» в последних сообщениях, кнопку убрать) и пропавшие (последние сообщения удалить);
по каждой открытой с `next_send_at <= now` и в окне — удалить прежние сообщения, отправить
новое в каждый заданный чат, запомнить номера, `next_send_at = +30 минут` (в окне). Ошибки
Telegram: удалить/изменить не вышло (старое, удалено руками) — пропустить; отправка в один
чат упала — лог, второй чат и остальные заказы идут дальше; `next_send_at` сдвигается
всё равно (без частых повторов).

**Кнопка** — `callback_data` со своим префиксом и номером записи; нажимать может любой в
чате; обновление «только если открыто» (как у «Неразобранного»); удалось — в обоих чатах
«Отложено до завтра — <имя нажавшего>», без кнопки, `next_send_at` = завтра 10:00; уже
проведён / закрыт — короткий ответ на нажатие и кнопку убрать.

## Задачи

### Задача 1. Таблица, правила времени, кандидаты и «проведён»

- Миграция 0018 (идемпотентная, как 0014) — **не применять на сервере**.
- Модуль `notifications/order_close_reminder.py`: время, окно, текст, названия услуг — с
  тестами (границы окна 09:59 / 10:00 / 19:59 / 20:00, первое напоминание не раньше
  `order_date+1 10:00`, «завтра» после 20:00 и до 10:00, текст по образцу из решения 4).
- Функция выбора кандидатов и проверки «проведён» в `bot.py` (запросы к базе) — тесты на живой
  базе (`TEST_DB_DSN`, образец изоляции — `tests/test_cleaning_olya_register.py`; представление
  `adminbot.calendar_jobs` в тестовой схеме заменить таблицей или представлением с теми же
  колонками): привязка по `calendar_event_id`; второй номер записи; заказ через неделю;
  клининг; удалённый заказ клининга не считается; запись старше 14 дней без открытого
  напоминания не берётся, с открытым — берётся; запись пропала из календаря.

### Задача 2. Рассылка, кнопка, выключатели

- Рассылка и кнопка по «Устройству»; выключатели `ORDER_CLOSE_REMINDER_ENABLED` (0 по
  умолчанию) и `STAFF_CHAT_ID` (0 по умолчанию) в `bot.py` рядом с соседними флагами;
  запуск в `on_startup` как у «Неразобранного».
- Тесты с подменённым ботом Telegram (записывает отправки, удаления, правки) и подменёнными
  часами: до `order_date+1 10:00` — ничего; в 10:00 — по сообщению в каждый чат; через 30 минут —
  старые удалены, новые отправлены; в 20:00 и ночью — ничего; «Напомнить завтра» — правка в
  обоих чатах, до завтра 10:00 тишина, завтра снова; провели — «✅ Заказ проведён», дальше
  тишина; пропала из календаря — удалено, тишина; `STAFF_CHAT_ID=0` — только один чат;
  выключатель выключен — ничего; отправка в один чат упала — второй получил.
