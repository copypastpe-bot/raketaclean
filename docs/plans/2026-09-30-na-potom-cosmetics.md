# ТЗ: косметика из списков «на потом» (п.13, 30.09)

Разрешение владельца 2026-09-30: косметику из списков «на потом» делает механик,
параллельно с работой координатора. Поведение ботов не меняется ни в одном пункте:
только комментарии, документация, `.gitignore`, текст строки отчёта обёртки, один тест.

Источники пунктов: `docs/plans/2026-09-23-amo-unsorted-cards-fixes.md`,
`docs/plans/2026-09-23-promo-autocall-fixes.md`, `docs/plans/2026-09-28-feedback-tasks-fixes.md`.

## Общие правила для исполнителя

- Первым шагом: `git rev-parse --short HEAD` и сверка с SHA из промпта. Не совпало — стоп и доклад.
- `git stash`, `git worktree`, `git merge`, `git push` — запрещены. В репозитории параллельно
  работает координатор: `git status --short` до начала и перед каждым коммитом, в индекс —
  только свои файлы, поимённо.
- Поведение кода не менять. Если пункт требует решения («как правильно?») — не решать,
  записать под задачей «Нужно решение: …» и идти дальше.
- Каждая задача — отдельный коммит; после коммита отметка «Выполнено: <дата>, <SHA>» под задачей.
- Тесты — только затронутые файлы, вывод через `tail`:
  админ-бот — `cd raketa-admin-bot && TEST_DB_DSN=postgresql://postgres@127.0.0.1:5432/adminbot_test rtk proxy .venv/bin/python -m pytest <файл> -q --tb=short`;
  рабочий бот — `TEST_DB_DSN=postgresql://postgres@127.0.0.1:5432/raketaclean_test rtk proxy .venv-wahelp/bin/python -m pytest <файл> -q --tb=short`;
  служба оповещений — по `raketa-notify/` (база `notify_test`).
- Файл длиннее 500 строк — сначала его карта `<файл>.map.md`, потом нужный участок.
  Число строк файла изменилось — обновить номера в карте после места правки.
