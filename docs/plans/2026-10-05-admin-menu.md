# ТЗ: меню рабочего бота — кнопки админа, синее меню, /help, «мёртвое» меню

Дата: 2026-10-05. Решения владельца — в разговоре 05.10, перечислены ниже.
Рабочий бот (корень репозитория). Админ-бот не трогаем.

Базовый коммит: `bf74987` (`main`).

## Зачем

1. У админов половина кнопок не используется, клининга на кнопках нет, синее меню —
   22 пункта вперемешку, `/help` устарел.
2. **Баг:** админ часто получает «Команда не распознана. Выберите действие на клавиатуре
   ниже.», оживляет только `/start`.

## Причина бага (разбор координатора, факты по коду `bf74987`)

- Кнопки главного меню админа, кроме «Отчёты», срабатывают только в состоянии
  `AdminMenuFSM.root` (`grep -n 'AdminMenuFSM.root, F.text' bot.py`; «Отчёты» — `bot.py:7170`
  без фильтра состояния).
- Состояние теряется: (1) при каждом перезапуске — `dp = Dispatcher()` (`bot.py:430`) хранит
  состояния в памяти; (2) `cancel_any` (`bot.py`, ~12780) чистит состояние и показывает
  `admin_root_kb()`, не ставя `root`; (3) около дюжины завершений операций делают так же
  (проверка координатора скриптом: 13 мест из 99 с `reply_markup=admin_root_kb()` без
  `AdminMenuFSM.root` рядом — эвристика, не полный список).
- Заглушка `unknown` (`bot.py`, ~14790, `StateFilter(None)`) показывает админу клавиатуру,
  но состояние не ставит — следующее нажатие снова в заглушку, по кругу до `/start`.
- У мастеров и Оли бага нет: их кнопки привязаны к тексту без состояния
  (`bot.py:12937`, `14447`, `14487`…; мост клинера `cleaner_button_bridge`).

## Решения владельца (05.10)

1. **Кнопки внизу у админа** (`admin` и `superadmin` одинаково):
   - главное меню: **Операции**, **Отчёты**, **Клиенты**, **Клининг**. Кнопки «Мастера» нет;
   - **Операции**: `[Приход, Расход, Изъятие]`, `[Привязать, Рассчитать ЗП]` — то, что сейчас
     эти кнопки делают в главном меню;
   - **Отчёты**, **Клиенты** — как сейчас;
   - **Клининг**: `[Приход, Расход, Баланс]`, `[Перемещение, Выплата прибыли]`.
     Приход — `/cleaning_cash_add`; Расход — единый расход (решение 2); Баланс —
     `/cleaning_balance`; Перемещение — `/cleaning_move`; Выплата прибыли — `/cleaning_dividend`.
     «Провести уборку» у админа нет (проводят только бригадиры — решение 05.10 остаётся).
2. **Расход клининга — один сценарий для всех**: сумма → категория → источник → комментарий →
   «Провести» (нынешний `/cleaning_expense`, `foreman_expense_start`). Оля источник не выбирает —
   всегда «Деньги Ольга»; админ выбирает всегда. Вторая команда **`/cleaning_cash_expense`
   удаляется** вместе со своим сценарием.
3. **Синее меню** (описания — дословно):
   - **без роли, клинер, мастер**: `/start` «Открыть меню», `/help` «Помощь»;
   - **admin (Дима)**, в этом порядке:
     `/start` «Открыть меню», `/help` «Помощь», `/order` «Добавить заказ»,
     `/dividend` «Выплата дивидендов», `/investment` «Внесение инвестиций»,
     `/jenya_card` «Баланс Карты Жени», `/add_master` «Добавить мастера»,
     `/list_masters` «Список мастеров», `/masters_all` «Полный список мастеров»,
     `/remove_master` «Деактивировать мастера», `/cleaning_cash_withdrawal` «Клининг: изъятие из кассы»,
     `/cleaning_move_delete` «Клининг: удалить перемещение», `/cleaning_olya` «Клининг: Деньги Ольга»;
   - **superadmin**: всё, что у admin, и в конце: `/order_remove` «Удалить заказ»,
     `/tx_remove` «Удалить транзакцию», `/bonus_backfill` «Пересчитать бонусы»,
     `/cleaning_cancel_order` «Клининг: отменить уборку», `/cleaning_dividend_cancel` «Клининг: отменить выплату».
4. **`/help`**:
   - без роли, клинер, мастер: `Если возникли проблемы, напишите @pastushenko12`;
   - admin: список команд, которых нет ни на кнопках, ни в его синем меню (решение владельца;
     состав — ниже, «Состав `/help` админов»); superadmin — то же плюс свои.
5. **Удалить из бота совсем**: `/import_amocrm`, `/upload_clients`, `/import_leads_dryrun`,
   `/import_leads`, `/db_apply_cash_trigger` (на проде старых триггеров на `orders` нет —
   проверено координатором 05.10, команда ничего не делает), `/cleaning_cash_expense` (решение 2).
6. Кнопки «Сдать Диме» у Оли нет; перемещает только админ. Меню мастеров и Оли (кнопки внизу)
   не меняются.

Решения координатора (владелец видел 05.10): главное меню в два ряда `[Операции, Отчёты]`,
`[Клиенты, Клининг]`; в подменю Операции и Клининг последний ряд — `[Назад]` (в главное меню);
после операции из кнопки «Клининг» (успех, отказ, «Отмена»/«Отменить») админ возвращается в
главное меню админа, у Оли — как сейчас; «Кто я» убрана из синего меню у всех; код старой
кнопки «Мастера» удаляется, команды мастеров работают; новые меню у людей — после перезапуска.

## Устройство (решения координатора)

- **Правило кнопок админа (починка бага).** Кнопка с уникальным текстом (главное меню:
  Операции, Отчёты, Клиенты, Клининг; подменю: Изъятие, Привязать, Рассчитать ЗП, Баланс,
  Перемещение, Выплата прибыли) срабатывает у человека с правом, **когда он не внутри
  сценария** — состояние `None` или любое состояние `AdminMenuFSM` — без `/start`. Право
  проверяется внутри, как сейчас.
- **«Приход» и «Расход»** есть в двух подменю — их различает состояние подменю
  (`AdminMenuFSM.operations` / `AdminMenuFSM.cleaning`, новые). Без состояния (после
  перезапуска) — ответ «Выберите раздел:» с главным меню админа, **без** «Команда не распознана».
- `cancel_any` и `unknown` для админа ставят `AdminMenuFSM.root` вместе с главным меню
  (страховка; главное — правило выше).
- Кнопки внутри клининговых сценариев (их FSM) заглушка не ловит и сейчас (`StateFilter(None)`),
  так и остаётся.
- `admin_root_kb()` живёт в `bot.py`, клининговые обработчики — в `cleaning/handlers.py`.
  Возврат админа в главное меню после клининговой операции — без циклического импорта
  (способ — на усмотрение исполнителя; образец передачи общих вещей роутеру — `dp["pool"]`).

### Состав `/help` админов

Команды, которые человек с этой ролью может выполнить, но которых нет ни на его кнопках,
ни в его синем меню. Строка: команда, формат аргументов (из обработчика), что делает — коротко.
Группы: «Химчистка», «Клининг».

- admin: `/whoami`, `/orders`, `/tx_last`, `/cash_balance`, `/daily_cash`, `/daily_profit`,
  `/daily_orders`, `/my_daily`, `/mysalary`, `/myincome`, `/cleaning_cash`, `/cleaning_orders`.
- superadmin: то же плюс `/tx_delete`.
- Не включать: дубли `/start` (`/admin_menu`, `/admin_panel`); команды, чья работа есть на
  кнопках (`/find`, `/client_*`, `/income`, `/expense`, `/withdraw`, `/link_payment`, `/reports`,
  `/cash`, `/profit`, `/payments`, `/payroll`, `/cleaning_expense`, `/cleaning_cash_add`,
  `/cleaning_move`, `/cleaning_dividend`, `/cleaning_balance`); `/cleaning_order` (админу недоступна).
- Список выше — решение по составу. **Найди все** команды бота (`grep -oE 'Command\("[a-z_]+"' bot.py cleaning/*.py`)
  и проверь, что каждая после работы попадает ровно в одно: кнопки / синее меню / `/help` /
  «не включать» выше / удалена. Неучтённая — в отчёт координатору, не додумывать.
