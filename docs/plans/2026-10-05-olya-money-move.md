# ТЗ: «Деньги Ольга» и перемещение денег клининга

Дата: 2026-10-05. Решения владельца — в разговоре 05.10, перечислены ниже.
Рабочий бот (корень репозитория). Продолжение ТЗ `docs/plans/2026-10-05-olya-money-register.md`
(реестр денег Оли, в бою с 05.10). Админ-бот, `analytics_app/`, меню и `/help` не трогаем.

Базовый коммит: `30e62eb` (`main`).

## Зачем

1. «Деньги Оли» читается как личные деньги Ольги, а это рабочие деньги компании. Копилка
   называется «Деньги Ольга» — по образцу «Карта Женя» в химчистке, без принадлежности.
2. Когда Ольга отдаёт наличные Диме (или Дима выдаёт ей), сейчас нужны две операции —
   изъятие из денег Оли и внесение в кассу Димы; касса клининга при этом проседает и
   возвращается. Нужна одна операция «перемещение» между двумя кучками, при которой вся
   касса клининга не меняется, и её удаление.

## Решения владельца (05.10)

1. Вместо «Деньги Оли» везде, где это видит человек, — **«Деньги Ольга»**. Вопрос админу
   «Из чьих денег? …» → **«Источник? …»**. Вопрос на приходе «Куда вносим? …» остаётся
   (меняется только название копилки в нём). Кнопки «Оля» / «Дима» и строка Ольги
   «У вас на руках» не меняются. Пункт синего меню «Клининг: деньги Оли» — **не трогать**
   (переименуют с переделкой меню).
2. **Перемещение** — команда админов (оба: `admin` и `superadmin`, право
   `cleaning_manage_cash`), в обе стороны: «Деньги Ольга» ↔ «Касса (Дима)».
3. **«Касса (Дима)» = вся касса клининга − «Деньги Ольга»** (`get_cleaning_balance` −
   `get_olya_balance`). Две кучки в сумме всегда дают всю кассу.
4. **Больше остатка кучки-источника переместить нельзя.** Остаток показывается на шаге
   ввода суммы.
5. Сообщение в чат клининговых денег (`send_cleaning_money_flow`) — без строки
   «Итоги по кучкам», сразу названия и суммы:

   ```
   🔁 Перемещение денег
   Деньги Ольга → Касса (Дима): 10 000₽
   Комментарий: …            ← только если введён

   Деньги Ольга: 3 500₽
   Касса (Дима): 51 024₽
   ```

6. **Удаление перемещения** — отдельной командой, по образцу отмены выплаты
   (`/cleaning_dividend_cancel`, `cleaning/handlers.py`): без номера — список последних,
   с номером — подтверждение «Провести». Сообщение в чат:

   ```
   🗑 Перемещение #N удалено
   Деньги Ольга → Касса (Дима): 10 000₽

   Деньги Ольга: 13 500₽
   Касса (Дима): 41 024₽
   ```

7. **Удалить нельзя, если после удаления кучка уйдёт в минус** — ответ вида
   «Нельзя: в «Деньги Ольга» станет −3 000₽.»

Решения координатора (владелец видел, 05.10): команды `/cleaning_move` и
`/cleaning_move_delete`; на вопрос «Откуда?» кнопки названы кучками — «Деньги Ольга»,
«Касса (Дима)»; остаток перепроверяется в момент «Провести»; в отчёт `/cleaning_cash`
перемещения не попадают, в `/cleaning_olya` — видны; в списке для удаления 10 последних;
изъятие и внесение клининга остаются как есть.

## Устройство (решение координатора; факты — по коду на `30e62eb`)

- Перемещение — **одна строка** `cleaning_cashbook` нового вида `kind = 'move'`.
  Ограничения на `kind` в таблице нет (`app/migrations/0006_cleaning.sql:47`,
  `cleaning/schema.py:75`) — **миграции не нужно**.
- `cash_holder` строки перемещения — **кучка-источник**: `'olya'` — «Деньги Ольга →
  Касса (Дима)», `'dima'` — «Касса (Дима) → Деньги Ольга». Направление определяется
  только по `cash_holder`.
- `method` (NOT NULL) — подпись маршрута для людей: `«Деньги Ольга → Касса (Дима)»` или
  `«Касса (Дима) → Деньги Ольга»`. Логика по `method` не ветвится.
- Удаление — `deleted_at = now()` у этой строки.
- Вся касса: `get_cleaning_balance` (`cleaning/cashbook.py:191`) считает только известные
  виды, у прочих `ELSE 0` — перемещение её не меняет само. **Проверь тестом.**
- `get_olya_balance` (`cleaning/cashbook.py:218`): к нынешней формуле добавить
  `move` с `cash_holder='olya'` → минус, `move` с `cash_holder='dima'` → плюс.
- `list_olya_entries` (`cleaning/cashbook.py:249`): показывать и строки
  `kind='move' AND cash_holder='dima'` (перемещения к Ольге).
- Отчёт `/cleaning_cash` (`get_cleaning_cash_report`, `cleaning/cashbook.py:90`) кладёт
  неизвестный вид в `by_kind` через `setdefault`; убедись тестом, что ни одна сумма отчёта
  (приход, расход, DIV, изъятия, внесения, прибыль) от перемещения не меняется.
- Проверка «не больше остатка» и проверка «удаление не уводит в минус» — дважды: на шаге
  ввода (чтобы подсказать сразу) и **внутри транзакции записи** перед `INSERT`/`UPDATE`.
  Для перемещения и удаления взять `pg_advisory_xact_lock` с постоянным ключом (две
  такие операции не пересекутся; прочие операции кассы замок не берут — это принято).

**Найди все** места, читающие `cleaning_cashbook` (`grep -rn "cleaning_cashbook" cleaning/ bot.py`),
и проверь, как каждое ведёт себя со строкой `kind='move'`. Неучтённое — в отчёт координатору,
не додумывать. `analytics_app/` сознательно не трогаем (см. «Чего не делать»).

### Задача 3. Команда `/cleaning_move`

Выполнено: c6f5467

- Право `cleaning_manage_cash`; без права — «Команда доступна только администраторам.»
  (как у соседних команд).
- Ход: «Откуда перемещаем?» (кнопки «Деньги Ольга», «Касса (Дима)», «Отмена») →

- После «Провести»: запись (задача 2); при отказе по остатку — ответ с текущим остатком,
  ничего не писать; при успехе — сообщение в чат по решению 5 и ответ админу

- Новая группа состояний в `cleaning/fsm.py`. «Отмена» на любом шаге: добавить группу в

  у `cancel_any` (`bot.py`). Помни: текстовые кнопки вне FSM ловит заглушка `unknown`

- Тесты обработчиков — по образцу `tests/test_cleaning_olya_choice.py`: оба направления,

### Задача 4. Команда `/cleaning_move_delete`

- Право `cleaning_manage_cash`.
- Без номера — «Последние перемещения:» и строки
  `#id — Деньги Ольга → Касса (Дима): 10 000₽, 05.10 14:00` (время московское, как у
  выплат), в конце `Удалить: /cleaning_move_delete N`. Нет ни одного —
  «Перемещений пока не было.»
- С номером: не найдено или уже удалено — «Перемещение #N не найдено или уже удалено.»;
  удаление уведёт кучку в минус — «Нельзя: в «…» станет −N₽.»; иначе
  «Удалить перемещение #N?» + маршрут и сумма + `_confirm_kb()`.
- «Провести»: удаление (задача 2) с повторной проверкой; сообщение в чат по решению 6;
  ответ админу «Перемещение #N удалено.»
