# Бриф — хвост по адресам: уборки

Дата: 2026-09-16
Автор: координатор, по решению владельца
Статус: **бриф, не ТЗ**. Требуется подготовить ТЗ до начала работы.

## Зачем этот документ

16.09 выполнена работа по ТЗ `2026-09-16-addresses.md`: адрес клиента больше не
вводится руками и приезжает из amoCRM сам. Девять задач из десяти сделаны, но
**контур уборок остался по-старому**. Причина простая: уборки живут в отдельном
модуле `cleaning/`, а исполнителям задач 3 и 5 был выдан список каталогов, в который
`cleaning/` не входил. Оба честно остались в границах и доложили о находке.

Этот бриф собирает факты, чтобы по нему написали ТЗ. **Сам он ТЗ не заменяет.**

## Что уже работает для уборок

Часть работы контур уборок получил сразу — она делалась в общих местах:

- колонка `deal_address` есть в **обеих** таблицах связок, включая `adminbot.cleaning_links`
  (миграция 012);
- админ-бот пишет туда адрес сделки — и при обычном заполнении, и на пути «уже сделано»
  (задачи 1 и 9);
- фоновый проход рабочего бота дозаполняет адрес **и для уборок тоже** — читает
  `public.cleaning_orders` и `adminbot.cleaning_links` (задача 4);
- карточка «сделка без адреса» с кнопками работает для уборок наравне с заказами
  (задача 7).

То есть труба проложена. Не переключён только вход и выход.

## Что осталось — три места

### 1. Бригадир вводит адрес руками

`cleaning/fsm.py:11` — состояния `address_choice` и `address`.
`cleaning/handlers.py:326–383` — диалог: сначала кнопки «Использовать этот адрес» /
«Другой адрес», затем ввод текстом.

Решение владельца 16.09: **адрес с мастера не спрашиваем никогда**. Для химчистки это
уже сделано (задача 3), для уборок — нет.

### 2. Сообщение о деньгах уходит сразу

`cleaning/notify.py:16` — `send_cleaning_money_flow`, свой чат
`CLEANING_MONEY_FLOW_CHAT_ID` (не тот, что у химчистки).
Вызовы — `cleaning/handlers.py:774` и `:913`.

По решению владельца сообщение должно ждать **появления связки** в
`adminbot.cleaning_links`, а не уходить в момент проведения. Предохранитель — 30 минут.
Для химчистки это сделано в задаче 5 через очередь `pending_order_reports`
(`app/migrations/0009`), и очередь стоит переиспользовать, а не заводить вторую.

### 3. Сигналы в чат ошибок

Задача 6 сделала два сигнала («сделка создана без адреса», «админ-бот не ответил
за 30 минут») только для заказов химчистки. Для уборок их нет.

## Препятствие, которое надо решить до кода

**Колонка адреса у уборок объявлена `NOT NULL`** — `app/migrations/0006_cleaning.sql:19`:

```sql
address        text NOT NULL,
```

У химчистки такого ограничения нет, поэтому там адрес просто перестал заполняться.
У уборок убрать вопрос бригадиру **нельзя** без миграции, снимающей `NOT NULL`, —
иначе уборка перестанет проводиться вовсе.

Это единственное место, где хвост по уборкам сложнее, чем то же самое для химчистки.

## Условие начала работы

Владелец решил 16.09: **сначала его живая проверка** механики на настоящем заказе
химчистки, и только потом уборки. Причина — сегодня выкатывается большое изменение
в оба бота; проверять его на одном контуре дешевле, чем на двух сразу.

Пока проверка не прошла, за уборки не браться.

## Что требуется сделать по этому брифу

**Подготовить ТЗ** в `docs/plans/` по образцу `2026-09-16-addresses.md`. В нём:

1. Разложить три места выше на задачи с проверками и отметками «Выполнено».
2. Отдельной задачей — миграция, снимающая `NOT NULL` с `cleaning_orders.address`,
   и решение, чем заполнять колонку у заказов, проведённых до дозаполнения
   (пустая строка или NULL — решить и записать явно).
3. Указать, что очередь `pending_order_reports` переиспользуется, а не дублируется.
4. Указать каталоги исполнителю **явно, включая `cleaning/`** — сегодняшняя дыра
   родилась именно из-за пропущенного каталога.
5. Прописать порядок выката и приёмку владельцем.

## Что не обсуждено с владельцем и требует его слова

- **Адрес в карточке клиента у уборок.** Сегодня диалог предлагает «использовать этот
  адрес» из карточки. После переключения на CRM карточка станет только приёмником.
  Нужно ли оставить бригадиру возможность поправить адрес в исключительном случае —
  не спрашивали.
- **Заказы уборок вне календаря.** У химчистки такой заказ остаётся без адреса и
  порождает карточку-напоминание. Для уборок поведение не обсуждалось отдельно.
